### Database Models (Prisma Schema Analysis)

**Core Multi-Tenancy Models:**
- `Tenant` - Represents each school/institution
- `User` - Global user account
- `SaaSSuperAdmin` - Platform-level super admin
- `TenantSuperAdmin` - School-level master admin
- `TenantRole` - Custom roles per tenant
- `TenantPermission` - Actions and Subjects with Scope
- `TenantUserRole` - User-to-role assignment with expiration
- `TenantRolePermission` - Role-to-permission mapping

**Key Feature:**
- **Tenant Isolation** via `tenantId` field on all domain models
- **RBAC with Scopes**: ALL, DEPARTMENT, OWN_ONLY
- **Audit Trail**: Full `TenantAuditLog` with actor tracking
- **Role Versioning**: `RoleChangeAudit` tracks permission changes

## ðŸŒŒ Anti-Gravity Navigation Concept

### Understanding Anti-Gravity

The term "anti-gravity" in navigation suggests navigation that defies normal hierarchical flow. In a SaaS multi-tenant system, this means:

```
Traditional Hierarchy (Linear):
User â†’ Role â†’ Department â†’ Permissions
       â†“
       Locked into single path
       Cannot move laterally

Anti-Gravity (Fluid):
    â”Œâ”€â†’ Can access multiple roles
    â”‚
User â”€â†’ Multi-role assignment (Teacher + Department Head)
    â”‚
    â””â”€â†’ Context-aware permissions (Different in each class)
```

### Implementation Strategy

#### 1. **Multi-Role Assignment**

A single user can hold multiple roles simultaneously:

```typescript
// User is both Teacher AND Department Head
const userRoles = [
  { roleId: "teacher_id", tenantId: "school_1", expiresAt: null },
  { roleId: "dept_head_id", tenantId: "school_1", expiresAt: "2025-12-31" }
];

// They see both navigations:
// As Teacher: Classes, Attendance, Grades
// As Dept Head: Teachers, Budget, Reports

// Role Switching UI:
<RoleSwitcher roles={userRoles} />
// "Currently viewing as: Department Head [Switch to Teacher â†’]"
```

#### 2. **Context-Switching Navigation**

Navigation changes based on context (which class, which department):

```typescript
// Teacher viewing Class A:
/teacher/classes/classA/students
/teacher/classes/classA/attendance
/teacher/classes/classA/grades

// Same teacher viewing Class B:
/teacher/classes/classB/students
/teacher/classes/classB/attendance
/teacher/classes/classB/grades

// The sidebar dynamically updates for each class
```

#### 3. **Scope-Based Navigation**

Permissions change based on scope:

```typescript
// Same user, different permissions:

As FINANCE_ADMIN (Scope: ALL):
â”œâ”€ Can view all fees
â”œâ”€ Can view all payments
â””â”€ Can approve all transactions

As DEPARTMENT_HEAD (Scope: DEPARTMENT):
â”œâ”€ Can view department fees only
â”œâ”€ Can view department payments only
â””â”€ Cannot approve (no approval permission)

// Navigation reflects this:
if (permission.scope === "ALL") {
  sidebarItems.push("All Fees");
} else if (permission.scope === "DEPARTMENT") {
  sidebarItems.push(`${department.name} Fees`);
}
```

#### 4. **Temporal Role Expiration**

Roles can be temporary:

```typescript
const tempRole = {
  roleId: "interim_head_id",
  tenantId: "school_1",
  expiresAt: "2025-06-30" // Role ends after this date
};

// Middleware checks expiration:
function checkRoleExpiration(req, res, next) {
  const roles = req.user.tenantRoles;
  const activeRoles = roles.filter(r => !r.expiresAt || new Date(r.expiresAt) > new Date());
  
  if (activeRoles.length === 0) {
    return res.status(403).json({ error: "No active roles" });
  }
  
  req.activeRoles = activeRoles;
  next();
}
```

#### 5. **Cross-Tenant Navigation (Super Admin)**

SaaS super admin can impersonate tenants:

```typescript
// SaaS Admin sees:
/saas-admin/dashboard (Platform view)
/saas-admin/tenants/[id]/impersonate (View as that tenant admin)

// When impersonating:
/impersonate/tenant_123/admin/dashboard
// This temporarily sets tenantId for all requests

// Backend enforces:
if (req.user.saasSuperAdmin && req.query.impersonateTenantId) {
  req.tenantId = req.query.impersonateTenantId; // Allow cross-tenant viewing
}
```

#### 6. **Dynamic Sidebar Generation**

Instead of static sidebars, generate based on actual permissions:

```typescript
// WRONG: Hardcoded sidebar
const adminSidebar = [
  { title: "Users", url: "/admin/users" },
  { title: "Finances", url: "/admin/finances" },
  // ... etc
];

// RIGHT: Permission-based sidebar
async function generateSidebar(userId, tenantId) {
  const roles = await getActiveRoles(userId, tenantId);
  const permissions = await getPermissionsForRoles(roles);
  
  const items = [];
  
  if (permissions.some(p => p.subject === "USERS")) {
    items.push({ title: "Users", url: "/admin/users" });
  }
  if (permissions.some(p => p.subject === "FINANCE")) {
    items.push({ title: "Finances", url: "/admin/finances" });
  }
  
  return items;
}
```

#### 7. **Permission-Aware Component Rendering**

```typescript
// Components check permissions before rendering:
export function AdminPanel({ userId, tenantId }) {
  const [permissions, setPermissions] = useState([]);
  
  useEffect(() => {
    fetch(`/api/users/me/permissions?tenantId=${tenantId}`)
      .then(r => r.json())
      .then(p => setPermissions(p));
  }, [userId, tenantId]);
  
  const can = (action, subject, scope) => {
    return permissions.some(p => 
      p.action === action && 
      p.subject === subject && 
      (p.scope === "ALL" || p.scope === scope)
    );
  };
  
  return (
    <div>
      {can("READ", "USERS", "ALL") && <UsersList />}
      {can("UPDATE", "ROLES", "ALL") && <RoleManager />}
      {can("CREATE", "ANNOUNCEMENTS", "ALL") && <AnnouncementForm />}
    </div>
  );
}
```

### Anti-Gravity Navigation Benefits

1. **Flexibility**: Same person can do multiple jobs
2. **Scalability**: Add roles without breaking UI
3. **Audit Trail**: Know exactly what each user can do
4. **Temporal Roles**: Support internships, consultants, temp staff
5. **Zero Hardcoding**: Sidebar/permissions are always dynamic
6. **Compliance**: Easier to prove who had access to what
